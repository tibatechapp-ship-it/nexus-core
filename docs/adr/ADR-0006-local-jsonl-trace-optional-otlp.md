# ADR-0006: أثر محلي JSONL + مُصدِّر OTLP اختياري — بلا SDK

- **الحالة**: مقبول (2026-11 — م3/v1.55.0)
- **السياق**: أنظمة التتبّع السائدة (OTel SDK وغيره) تجرّ تبعيات
  وتفترض عملية خادم — يكسران ADR-0001 والهاتف.
- **القرار**: أثرنا ملفات JSONL محلية بمخطط مثبَّت
  (`nexus.trace/v1`) بمعرّفات متوافقة **مفاهيميًا** مع OTel
  (trace_id 32hex/span_id 16hex/parent)؛ من يريد التصدير يفعّل
  `NEXUS_OTLP_ENDPOINT` فيبني `OTLPExporter` جسم OTLP/JSON قياسيًا
  **بعملية urllib واحدة** — بلا SDK وبلا عميل.
- **النتائج**: replay بصري في PWA من الملف نفسه؛ دوران 5MB مع
  ضغط zlib بسقف قرص معلن؛ لسنا «متوافقين مع OTel» كاملًا ونعلن
  الحد: بلا بث حي ولا sampling.
- **البدائل المرفوضة**: اعتماد OTel SDK — عكس ADR-0001؛ منصات
  تتبّع سحابية — عكس ADR-0004.
