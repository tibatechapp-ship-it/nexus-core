# ADR-0004: الخصوصية افتراضية — لا صادر إلا بسماح صريحة

- **الحالة**: مقبول (2026-11 — م3/v1.55.0 وم4/v1.56.0)
- **السياق**: التتبّع العميق يخلق خطر تسريب محتوى المستخدم إلى
  الخارج؛ التشغيل البيني (A2A) يخلق خطر اتصالات صادرة غير مقصودة.
- **القرار**: **كل قناة صادرة مغلقة افتراضيًا** وتُفتح بضمّان صريح:
  * OTLP: لا يُصدَّر أثر إلا بضبط `NEXUS_OTLP_ENDPOINT`.
  * A2A: لا اتصال إلا لمضيف في `NEXUS_A2A_ALLOWLIST` — وبطاقة
    الندّ نفسها (card.url) تمرّ بالفحص هو الآخر (لا SSRF).
  * سمات الأثر: مرشّح دفاعي يسقط المفاتيح الحاملة للمحتوى
    (prompt/content/...) عند الإنشاء وعند الكتابة.
- **النتائج**: «يعمل على الهاتف بلا سحابة» يبقى حرفيًا؛ الفشل
  الشبكي best-effort لا يُسقط العمل المُتتبَّع أبدًا.
- **البدائل المرفوضة**: opt-out (تتبّع مفعّل يتطلب تعطيلًا) — يكسر
  وعد الخصوصية عند أول إهمال.
