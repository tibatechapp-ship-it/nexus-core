# الهندسة العكسية للأنظمة المتحكّمة بتقنية الوكلاء — تفكيك معماري كامل

> تاريخ: 2026-11-05 · النطاق: LangGraph · AutoGen/Microsoft Agent Framework ·
> CrewAI · OpenAI Agents SDK · (مرجعية مساندة: Pydantic AI)
> المنهجية: تفكيك التوثيق الرسمي + الأبحاث المنشورة + تحقيقات الإنتاج المستقلة،
> ثم استخلاص **القرار المعماري** خلف كل ميزة، واختبار كل قرار ضد أهدافنا
> (خوصصة، عربي أولاً، stdlib خالص، حاكمية قابلة للتدقيق).
> الأخلاقيات: تحليل من مصادر علنية فقط — لا نسخ شيفرة، فقط استخلاص مبادئ.

## 1. لماذا الهندسة العكسية؟

الأنظمة الخمسة تحكرمز التقنية عبر ثلاث قنوات: (أ) الافتراضات السحابية المدمجة،
(ب) تعقيد يُستنزف منه المطور الجديد، (ج) شبكة تكاملات يصعب التقاطها. التفكيك
يكشف أن كل واحد منهم **يفكّك قصة واحدة**: كيف يُدار حال الوكيل؟ كيف يُدار
الانقسام بين العقول؟ كيف يُدار الفشل؟ من يملك البيانات؟ الإجابات هي خريطة
الطريق إلينا.

## 2. LangGraph (LangChain) — «آلة حالة دائمة» ونموذج Pregel

### 2.1 القرارات المعمارية المستخلصة

| المكون | القرار | التفصيل التقني |
|---|---|---|
| النموذج الذهني | **StateGraph**: State + Nodes + Edges | الحالة مخطط مشترك (TypedDict/dataclass/Pydantic)، العقد دوال تستقبل الحالة وتعيد تحديثاتها، الأحوال دوال تقرر التالي |
| محرك التنفيذ | **Pregel super-steps** (مستوحى من Google Pregel) | رسائل تمر عبر قنوات؛ العقد الفعّالة في نفس السوبر-ستيب توازى؛ تنتهي الدورة حين يخمت كل العقد — توازٍ + إنهاء محسومان بنموذج واحد |
| تحديث الحالة | **Reducers** لكل مفتاح | كل تحديث عقدة يُدمج بدالة reducer معلنة (استبدال/جمع/append) — لا سباق كتابة |
| الدومومة | **Checkpointers** عند كل سوبر-ستيب + **interrupt/resume** | التوقف للبشر (HITL) واستئناف بعد ساعات حالةً محفوظة — «فاز اللانغ-غراف لحظة انكسر شيء» في اختبار حقن فشل مستقل (9 خطوات، عطل مقصود: LangGraph استأنف من آخر نقطة، CrewAI أعاد من البداية وبانات مختلفة) |
| التوازي | **Send API** + Command (update+goto) | تفريع ديناميكي map/fan-out مع عودة مُجمَّعة |
| الحماية | compile-time checks + recursion limit | فحص بنائي عند `compile()`، حد تكرار محسوب |

### 2.2 مواطن الكسر (التي نستفيد منها)

- **ضريبة الصراحة**: تصميم State/nodes/transitions لمهام بسيطة أثقل من سكربت —
  منحنى تعلم شديد موثق حتى لـ 15–20 عقدة.
- الحالة تتدفق إلى منصة LangSmith افتراضيًا — ضد خصوصيتنا.
- لا «تعلم بين الجلسات»: الحالة دوّومة داخل دورة، لكن الوكلاء لا يرتفعون سمعيًا
  لأدائهم التاريخي.

### 2.3 ما نأخذه لـ nexus-core

1. **نقاط حفظ عند حدود المراحل** في المجلس والمنسّق (م2) — بـ stdlib: لقطات JSON
   موقّعة بـ hashlib لكل مرحلة تصنيف/توجيه/تفكيك/تحكيم، مع استئناف آمن.
2. **Reducers معلنة لدمج مخرجات الوكلاء** بدل الدمج الضمني في `merge_outputs`.
3. **حد تكرار محسوب** لأي حلقة تحكيم (عكس الحلقات المفتوحة).

## 3. AutoGen → Microsoft Agent Framework — قصة موت عملاق ودروس الوراثة

### 3.1 البنية قبل الأرشفة (v0.4)

طبقة **Core** بنموذج **Actors**: كل وكيل مُمثل بممثل حدثي، التواصل برسائل غير
متزامنة عبر runtime (داخليًا أو موزع gRPC)، + **AgentChat** كطبقة API عالية
(GroupChat متعدد الأدوار)، + **Studio** واجهة نمذجة بلا كود، + **Extensions**
(MCP workbench، منفذ كود Docker، توزيع gRPC).

### 3.2 الحدث الأكبر: الأرشفة والدمج

- **2025-10-02**: AutoGen يدخل وضع الصيانة رسميًا (إصلاحات حرجة فقط، لا ميزات).
- AutoGen + Semantic Kernel = **Microsoft Agent Framework 1.0**: workflow API
  قائم على الرسوم، routing آمن الأنواع، مسارات شرطية/متوازية، checkpointing،
  موافقات أدوات (tool approval)، وأنماط أوركسترا جاهزة (sequential / parallel /
  Magentic).

### 3.3 الدرس الاستراتيجي (الأثمن في هذه الوثيقة كلها)

**إطار يملكه راعٍ واحد يموت بموت استراتيجية الراعي.** 61 ألف نجمة و559 مساهمًا
لم تمنع الدفن. الاستنتاج لنا: الاستقلالية الكاملة (stdlib خالص، بلا راعٍ سحابي،
بيانات على الجهاز) ليست «قيودًا فرضناها على أنفسنا» بل **استراتيجية بقاء** —
نحن لا نستطيع أن نُؤرشف بموت منصة أحد.

### 3.4 ما نأخذه لـ nexus-core

1. نموذج الرسائل غير المتزامن عندنا (المجلس غير الحاجب) يوازي Actors —
   نقوّيه بعقود رسائل معلنة وتوثيق تسلسلات (م2).
2. **موافقة الأدوات** (tool approval) كمفهوم صريح — عندنا نرفعه إلى مستوى HITL
   مع تدقيق (م2/ض6).
3. Studio بلا كود دليل أن **الرؤية المُرئية** مطلوبة — PWA عندنا هي أساس
   «ترى التفكير» في الرؤية؛ نضيف إليها replay للمجالس (م3).

## 4. CrewAI — «فريق الأدوار» والمفارقة الموثقة للمدير الهرمي

### 4.1 البنية

- **Crews**: وكلاء بأدوار (role/goal/backstory) + مهام بثلاث أنماط تنفيذ
  (sequential / hierarchical مع manager_llm / مخصّص).
- **Flows**: طبقة حدثية أكثر حتمية (event-driven) للتحكم الدقيق، تُنشِّد Crews.
- **الذاكرة**: ChromaDB (قصيرة) + SQL (طويلة) + ذاكرة كيانات.
- التخلي عن LangChain كليًا عند 0.86 لصالح LiteLLM — قرار تقليل عقدة اعتماد
  عملاقة (نحن أصلًا في المتأخرين الصحيحين: صفر اعتماديات تشغيل).

### 4.2 النقد الأدبي القاتل (تحقيق TDS 2025-11)

«المدير الهرمي» — ميزة العرض الأشهر — **لا يفوّض فعليًا**: جميع المهام تُنفذ
تسلسليًا رغم اختيار hierarchical، لا تفرّع شرطي، والمخرج النهائي من آخر مهمة
لا من تركيب ذكي، مع استهلاك توكن مضخم. استنتاج المؤلف: «LLM مدبّر سيئ —
التنسيق المولّد تلقائيًا ميزة عرض لا ميزة إنتاج».

### 4.3 الدرس المزدوج لنا

**تحذير**: لا تبني «التنسيق الذاتي» على هبّة لغوية واحدة — هذا بالضبط ما تجنبناه
بتصميم المجلس: **بوابة محلفين إجرائية** (تصويت/إجماع محسوب) لا «مدير يقرر بمزاجه».

**تحذير معاكس**: CrewAI فازت سباق «أول 25 دقيقة» (وكيلان في 25 دقيقة مقابل ساعتين
في LangGraph) — **تجربة البدء** ميزة استراتيجية. PWA عندنا يجب أن تجعل «أول مجلس
يعمل» شأنًا من دقائق (م5: examples/ جاهز).

### 4.4 ما نأخذه لـ nexus-core

1. صياغة الأدوار بالعربية الواضحة (role/goal/backstory) موجودة عندنا في تعريفات
   الأسطول — نرّوثها في docs كـ «بطاقات وكلاء» قابلة للعرض (م5).
2. إدخال decorator موافقة بشرية مكافئ لـ `@human_feedback` لكن بوابة تدقيق
   كاملة (م2).
3. بنشمارك علنيًا ردًا على أرقامهم (5.76x claim) — من يزعم يُقاس (م5).

## 5. OpenAI Agents SDK — «البدائيات الخمس» وفلسفة القلة

### 5.1 البنية

- البدائيات: **Agent** (تعليمات + أدوات) · **Handoff** (تفويض وكيل→وكيل) ·
  **Guardrail** (تحقق مدخلات/مخرجات) · **Session** (ذاكرة سياق دائمة:
  SQLite/SQLAlchemy/مشفرة) · **Tracing** مدمج · **Realtime** صوتي.
- الفلسفة المعلنة: «بقدر كافٍ من الميزات ليستحق الاستخدام، وبأقل من البدائيات
  ليكون تعلمه سريعًا» — التنسيق بلغة Python ذاتها لا بتجريد جديد.
- تحويل أي دالة Python إلى أداة بمخطط تلقائي مُتحقق بـ Pydantic؛ دعم MCP؛
  تطوير إنتاجي لتجربة Swarm.

### 5.2 الدرس

**قوة الواجهة الصغيرة**: 5–6 بدائيات قابلة للحفظ في رأس تتفوق تسويقيًا وتشغيليًا
على 40 مفهومًا. عندنا المفاهيم الحقيقية قليلة فعلًا (وكيل/مجلس/منسّق/ذاكرة/بوابة)
لكنها غير معلنة كذلك — نعتمد رسميًا «البدائيات الخمس لنكسس-كور» في docs (م5).

### 5.3 ما نأخذه لـ nexus-core

1. **Guardrail كبدائية معلنة**: عندنا risk classify + jury gate + quality gate
   متناثرة المسمى — تجميعها تحت واجهة «سياج» موحدة موثقة (م2).
2. **Sessions** موثقة كمستوى ذاكرة سياق منفصل عن الذاكرة الدلالية — عندنا
   `src/sessions` موجود؛ توثيق الحدود بينه وبين `src/memory` (م1).
3. Handoff ↔ أسلوبنا: تفويضنا عبر المنسّق أغنى (مخاطر+تفكيك)، لكن نعلن
   handoff مباشر بين وكلاء الأسطول للتبسيط السريع (م2).

## 6. المعايير المالكة للسوق: MCP + A2A

- **MCP** (Anthropic): طبقة توصيل عالمية أدوات/سياق — عندنا منفذة stdlib بمراجعة
  2026-07-28. ✅ متقدّمون.
- **A2A** (Google): اكتشاف وتفويض وكلاء↔وكلاء عبر الأطر — Google ADK وPydantic AI
  دعماها أصلاً في 2026، ونحن غائبون عنها. ❌ فجوتنا المعيارية الوحيدة (م4).
- حكم السوق المعلن: «MCP وA2A هما معيارا التشغيل البيني الأساسيان لمنظومة
  وكلاء المؤسسات» — وغياب أحدهما = عزلة.

مجدولة في خطة v2 بمراحل مرقمة.

## 8. أخطاء المنافسين التي يُمنع علينا تكرارها

1. **لا مدير LLM ذاتي القرار** (مفارقة CrewAI): التنسيق إجراءات محسوبة لا نزوة
   لغوية — كل قرار وكيل يمر بوابة قابلة للتدقيق.
2. **لا مركزية راعٍ واحد** (موت AutoGen): بلا سحابة إلزامية ولا منصة تتبّع
   احتكارية؛ التتبّع ملفات محلية قابلة للتصدير.
3. **لا تجريد متضخم** (ضريبة LangGraph): البدائيات الخمس المعلنة، و«أول مجلس
   في دقائق» هدف تصميم.
4. **لا ادعاء بلا قياس** (أرقام 5.76x المنشورة): كل ميزة نعلنها معها اختبارها
   وبنچماركها القابل للتكرار.
5. **لا حالة متوهجة بلا حفظ** (اختبار حقن الفشل): أي سير طويل يُحفظ عند حدود
   المراحل — الفشل يُستأنف لا يُعاد.

## 9. الخلاصة التنافسية

التحكرم القائم يقوم على: سحابة المزوّد + تعقيد التجريد + حصر البيانات. الطريق
إلينا ليس «نسخهم أفضل» بل **المدخل الذي لا يملكونه**: مجلس حيّ يتعلم، يعمل على
جهازك، بالعربية، بلا سطر اعتمادية واحد، وبحاكمية مسجلة. المطلوب لتحويل هذا إلى
«نموذج رائد عالميًا» ليس مزيدًا من الوكلاء (فخ الرؤية المسمّى) بل: دومومة +
تتبّع + A2A + برهان منشور — وهي مراحل v2 الثلاث الأخيرة.
