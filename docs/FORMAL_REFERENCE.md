# البنية المرجعية الشكلية — إعادة هندسة عكسية إلى نواة stdlib

المبدأ الحاكم الوحيد المستعار من البنية المرجعية (AlphaProof / Lean 4 /
TLA+ / Dafny / CodeQL): **«الوكيل الذكي يبحث، والأداة الشكلية تحكم»**.
كل ما يلي هو ترجمة عكسية للبنية المرجعية إلى ما تستطيعه نواة nexus-core
(بايثون قياسي خالص، بلا اعتماديات، تعمل على هاتف) — بصدق كامل حول ما
يُنفَّذ وما لا يُنفَّذ.

## خريطة المستويات: المرجع ← التنفيذ ← الحد الصادق

| المستوى | الأداة المرجعية | ما ننفّذه فعلًا | الملف | الحد الصادق المعلن |
|---|---|---|---|---|
| 0 التنسيق | AlphaProof Nexus (4 وكلاء + بحث شجري) | حلقة الأدوار الأربعة: مولّد ← حاكم ← مصلح موجّه بالدليل ← منهي بميزانية صارمة؛ حتمية افتراضياً، قابلة للتركيب مع أي LLM | `src/formal/prover_loop.py` | بلا بحث شجري على حالات تكتيكات Lean — الميزانية خطية معلنة |
| 1 نمذجة البروتوكول | TLA+ + TLC | فاحص نماذج حالة-صريح: تعداد BFS محدود بـ`max_states`/`max_depth`، متغيرات سلامة بأثر خالق كامل، استقرار محدود (bounded stability) | `src/formal/model_checker.py` | **محدود فقط** — لا إثبات غير محدود، لا رمزية؛ تجاوز الميزانية = `UNKNOWN` مكتوب لا «سليم» |
| 2 إثبات الخصائص | Lean 4 kernel | عقد الحاكم: `Verdict` ثلاثي + `Judge` حتمي نقي + تركيب `all_accept` (UNKNOWN معدٍ) + إثبات بالسرد المحدود لمجال مُعلن | `src/formal/judge.py` | لا نظرية أنواع تابعة ولا kernel Lean — الإثبات هنا «سرد مُحدَّث» بمجال مُعلن لا برهان رياضي غير محدود |
| 3 صحة الخوارزميات | Dafny (SMT) | فاحص عقود: `requires`/`ensures` على دوال نقية بمجال مُعلن؛ مجال عاقر = `UNKNOWN` (عقد SKILLFORGE: المواصفة العاقرة لا تُشهّد نجاحاً)؛ مثال مضاد كامل عند الرفض | `src/formal/contract_checker.py` | بلا SMT — مجالات صغيرة معلنة؛ وللتحقق **بالتنفيذ** تبقى طبقة `src.verify` القائمة كما هي |
| 4 كشف الثغرات | CodeQL (QL) | MIZAN س6 القائم (DSL بصيغة JSON فوق `ast`) — والحلقة الوكيلية هنا تُغذّيه: الاستعلام اقتراح، وقاعدة MIZAN حاكمه | `scripts/mizan/mizan_rules.py` | مطابقة بسيطة — لا قاعدة بيانات علائقية ولا dataflow عبر الملفات في مستوى القواعد |

## العقود غير القابلة للتفاوض (من المرجع، حرفيًا)

1. **لا قبول إلا بحكم حاكم** — مخرج LLM أو الإنسان «مرشح» حتى يحاكم.
   `Verdict.require_accept()` هو البوبّة الوحيدة عبر البوابات.
2. **الحاكم حتمي ونقي** — نفس المدخل يعطي نفس الحكم؛ لا شبكة ولا
   عشوائية ولا حالة عالمية داخل أي حاكم.
3. **«تعذّر التحقق» ليس قبولاً** — `UNKNOWN` معدٍ في التركيب
   (`all_accept`) وفي الحلقة (توقف مع سبب مكتوب)، وأكواد الخروج
   الصادقة نفسها لدى MIZAN: `0` قبول / `1` رفض / `2` تعذّر.
4. **الإصلاح موجّه بالدليل لا عشوائي** — المصلح يستقبل المثال المضاد
   من الحاكم (عقد AxDafny/SKILLFORGE: تصنيف الخطأ يوجه المهارة).
5. **المواصفة العاقرة لا تُشهّد نجاحاً** — مجال فارغ بعد الشروط
   المسبقة = `UNKNOWN`، لا `ACCEPT` فارغ.
6. **الميزانية معلنة قبل التشغيل** — كل حد (states/depth/cases/
   attempts) مكتوب في التقرير، وكسره يُصرّح به.

## حلقة التغذية الراجعة المركزية (كما في المرجع)

فشل مستوى أدنى يعود سببه إلى مستوى أعلى:

```
REJECT في prover_loop
  ├─ counterexample من model_checker → العقد النموذجي ناقص أو الكود خاطئ
  ├─ counterexample من contract_checker → ensures ضعيفة أو الدالة خاطئة
  └─ unknown (ميزانية) → كبّر الميزانية المعلنة أو قلّص المجال — لا تخفي الحد
```

التقرير يحمل الأثر الكامل (المسار من الحالة الابتدائية للمخالفة، أو
المدخل+الناتج المضاد) — الفشل قابل للقراءة لا قابل للتخمين.

## ما لن نفعله (صراحة)

- **نواة Lean / SMT داخل النواة**: خارج قيود stdlib والهاتف تماماً؛
  الطبقة الشكلية هنا تُصدّر أحكامها كتقارير تُركّب مع أدوات خارجية
  (Lean/Dafny) إن أراد المشغّل — لا تتنافس معها ولا تدّعيها.
- **إثبات غير محدود**: كل ما نقدّمه محدود بميزانية معلنة — من يريد
  يقيناً غير محدود يستخدم Lean فعلاً؛ من يريد بوابة صادقة داخل نواة
  هاتف تستخدم هذه الطبقة.
- **جعل الحاكم قابلاً للتفاوض**: لا يوجد خيار «تقليل صرامة الحاكم» —
  يوجد فقط زيادة الميزانية المعلنة أو تعديل المواصفة المعلنة.
