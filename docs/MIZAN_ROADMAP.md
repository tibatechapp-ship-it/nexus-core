## س1 (v1.59.0) — محرك الإصلاح التلقائي: من «اقرأ فقط» إلى «خطط → عاين → طبّق»

> **الحالة: ✅ منفذة (2026-11-07)** — `src/mizan/` كاملة (مُحلّل بعدم
> متباين بايتي · نموذج إعلانات أوفلاين/OSV · مُخطِّط حتمي بتجفيف افتراضي) +
> `scripts/mizan/mizan_fix.py` + `mizan-fix.yml` بأقل صلاحية؛ 59 اختبارًا
> وتغطية 99.7% على الحزمة.

**الفجوة المقابلة**: Snyk يفتح Fix PRs تلقائيًا؛ MIZAN يترك العبء كله على
المطور.

**المبدأ المعتمد**: الإصلاح الحتمي قبل الأصحاح الذكي — خطط bump تُحسب من
بيانات الإعلانات لا من تخمين LLM، و**التجفيف (dry-run) هو الافتراض** والتطبيق
قرار صريح. الدروس المطبقة من ض10: لا `pull_request_target`، مسارات `git add`
صريحة، وأقل صلاحية على وظيفة فاتح الـ PR حصرًا.

**المكوّنات**:
- `src/mizan/advisories.py` — نموذج إعلان ثغرة + مصدران: ملف أوفلاين حتمي
  (CI/الاختبارات) وجلب OSV.dev اختياري (urllib بمهلة؛ فشله ⇒ وضع متدهور
  معلن، لا ارتباك).
- `src/mizan/manifest.py` — مُحلّل `requirements.txt` بجولة كاملة
  (تعليقات/ترتيب محفوظان)، تطبيع أسماء PEP 503، مُعامِلات `== >= <= ~= != < >`.
- `src/mizan/fixer.py` — المُخطِّط: لكل إعلان مستهدف تصحيح، أدنى إصدار مُصلح
  متسق مع مُعامِلات الملف الحالية (مثال: `>=1.2,<1.9` مصاب ⇒ `==1.9` لا قفزة
  كبرى)؛ `render_diff` عبر `difflib`، و`apply` يرفض التعديل الفارغ.
- `scripts/mizan/mizan_fix.py` — CLI: `plan` (افتراضي) / `apply` /
  `--diff-only` / `--advisories FILE` / `--osv`، أكواد خروج موثقة.
- `.github/workflows/mizan-fix.yml` — `workflow_dispatch` + `schedule` على
  main: يخطط، وإن وُجد فرق يفتح فرعًا `mizan/fix/<slug>` وPR واحدًا مجمعًا
  (صلاحية `contents: write` على هذه الوظيفة وحدها).

**بوابة الخروج**: اختبارات الانحدار تغطي المُحلّل والمُخطِّط والتطبيق والـ CLI
والوضع المتدهور؛ تغطية ≥95% على `src/mizan/`؛ لا PR يُفتح بلا فرق فعلي.

**المخاطر**: PR مفتوح بـ GITHUB_TOKEN لا يشغّل CI تلقائيًا (قيد GitHub معلن)
— يُعالج بتنفيذ مراجعة بشرية قبل الدمج كما هي سيرة Fix PRs التقليدية.

## س2 (v1.59.0) — Reachability: هل الكود يستدعي المصاب فعلًا؟

> **الحالة: ✅ منفذة (2026-11-07)** — `src/mizan/reachability.py` +
> `scripts/mizan/mizan_reach.py` + تكامل `--reachability` في `mizan_fix.py`.

- بناء رسم استيراد من الشجرة (`ast.Import`/`ImportFrom`) وتطبيع أسماء الحزم
  (pep503) لربط كل إعلان بوجهة استيراد فعلية.
- حكم ثلاثي لكل إعلان: `reachable` / `import-only` / `absent` — معلن في
  التقرير وفي JSON (`properties`).
- خفض أولوية غير القابل للاستغلال في مخرجات `mizan_fix.py --reachability`
  (ترتيب + تصنيف + ملاحظة «أولوية مخفضة») — **خفض لا حذف**: غياب الاستيراد
  المباشر ليس برهان عدم الاستخدام (حدود معلنة).
- **بوابة الخروج**: ✅ اختبارات على شجرة مرجعية (يستدعي / يستورد فقط / غائب
  + `__import__`/importlib محافظ) + خفض مثبت في تقرير الإصلاح.
