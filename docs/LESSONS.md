# Lessons learned — nexus-core

Durable engineering lessons from real incidents in this repo. Each entry names
the symptom, the root cause, and a prevention rule. Add here (not to
`AGENTS.md`) when a lesson is general and reusable.

## Manual metrics in docs always drift

**Symptom.** The framework test count was hand-updated in `README.md` at least
four times in one session: `3105 → 3408 → 3416 → 3445 → 3447`. Every fix was a
manual edit, and every one drifted again within days (the next commit that
touched the suite). Reports even cited four conflicting numbers (3442/3444/3446/
3447) in the same day.

**Root cause.** Any metric written as a literal in docs drifts on *every* commit
that changes the metric. Updating the number is treating the symptom, not the
cause. Same failure mode applies to `mypy (N files)`, coverage %, and line
counts in `AGENTS.md`.

**Rule.** A number in docs must be one of:
1. **live-linked** (a CI-generated badge / shields endpoint), or
2. **regenerated by CI/script** on release, or
3. **deliberately vague** (`3400+ tests`, `~99%`, `~120 lines`).

**Never** hand-fix an exact stale number — it *will* drift again. In this repo
the README now cites `3400+ tests @ ~99%`; the precise, always-true value comes
from the badge / `make check` output.

## gitignore patterns without a leading slash match anywhere

**Symptom.** A new tracked file `docs/legacy/AGENTS_HISTORY.md` was created, but
`git status` never showed it and `git add` did nothing — it was silently
ignored.

**Root cause.** The `.gitignore` rule was `legacy/` (UNANCHORED). A trailing-slash
directory pattern with no leading `/` matches that directory name at **any**
depth — so it matched both the intended root `legacy/` scratch dir **and**
`docs/legacy/`. Detectable only because the `AGENTS.md` diff showed −2131 lines
with no corresponding new tracked file.

**Prevention.**
- Anchor rules with a leading `/` when the intent is "repo root only":
  `/legacy/` not `legacy/`. Add a comment explaining the intent.
- After creating a file in a new directory, run
  `git check-ignore -v <path>` — it must print nothing (exit non-zero).
- When a diff shows deletions without matching additions, suspect a silently
  ignored new file before suspecting the edit itself.

Same class of "silent hiding" seen elsewhere this project:
- `/memory/` gitignored → 33 MB of local state hidden;
- `--ignore=tests/novamind` → 54 tests invisible to the default gate.
Always verify with the tool (`check-ignore`, `git status --ignored`,
`pytest --co`) rather than assuming.

## Read endpoints must be pure

A `GET` must not change state. In v1.30.0 the maintenance task ledger was written
both at generation time (inside `generate_tasks()`) and again by the caller — so
merely calling the read/metrics path twice inflated the counts. Fix: the planner
is pure; only the script that performs a real mutation writes the ledger.
**Test rule:** call the GET twice and assert state-before == state-after.

## Never diagnose API behaviour from a screenshot

Two "bugs" reported against v1.30.0 (Arabic keys, a missing `high_pct`) were
artifacts of a machine-translated browser screenshot. The live HTTP contract had
lowercase English keys and never lacked the field. **Always read the real
contract with `curl` before filing or fixing.**
