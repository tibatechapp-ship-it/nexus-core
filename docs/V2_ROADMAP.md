## 1. المبادئ الحاكمة (الخمسة)

1. **كل ميزة بأدواتها**: لا ميزة تدخل main بلا اختبار يثبت سلوكها وبوابة CI تمنع تراجعها.
2. **الصراحة قبل الذكاء**: التنسيق بإجراءات محسوبة لا بمزاج LLM (درس CrewAI §8-1).
3. **الفشل يُستأنف لا يُعاد** (درس LangGraph §8-5): أي سير طويل يُحفظ عند حدود مراحله.
4. **كل ادعاء مُقاس**: لا رقم في docs بلا بنشمارك يولّده سكربت في `scripts/`.
5. **لا نموّ وكلاء** (فخ الرؤية المسمّى): 106 وكلاء ثابتون — التطوير في عمق
   المجلس والدومومة والبرهان، لا في عدد العقول.

## 3. المرحلة 1 (م1) — توحيد الجذر: مصدر واحد للحقيقة · v1.53.0 · أسبوعان (2026-11-09 → 11-20)

> **الحالة: ✅ منفذة (2026-11-05، قبل الموعد)** — 18 ملفًا هاجرت إلى
> `src/legacy_root/`، بوابة `tests/test_root_hygiene.py` خضراء، 4137 اختبارًا
> ناجحًا وتغطية ≥95% وتقارير الأسطول مجدّدة عند 1.53.0. المتبقي من م1:
> إعادة تقييس legacy_root تدريجيًا (مُجدول ضمن م3).

**الهدف**: القضاء على ض4 — كل بايت كود حي يعيش تحت `src/`.

- نقل الـ 19 ملفًا الحرة من الجذر (`hyper_agent.py`, `registry_full.py`,
  `review_engine.py`, …) إلى وحدات `src/` المناسبة، مع `__getattr__` رجعي في
  وحدة توافق لمدة إصدار واحد (deprecation صريح بمسار ترقية موثق).
- توثيق حدود `src/sessions` مقابل `src/memory` (من الدرس §5.3) في docs/ARCHITECTURE.md.
- `legacy/` يُجمَّد رسميًا (README تحذيري + استثناء من التغطية، لا حذف).

**بوابة الخروج**: صفر `.py` في جذر المستودع (باستثناء `main.py` نقطة الدخول) —
اختبار `tests/test_root_hygiene.py` يفشل CI عند أي إضافة جذرية جديدة.
**المخاطر**: كسر مسارات استيراد خارجية → تعالجه وحدة التوافق + فحص grep آلي.

## 4. المرحلة 2 (م2) — التنفيذ الدوّم والواجهة البشرية · v1.54.0 · 4 أسابيع (2026-11-23 → 12-18)

> **الحالة: ✅ الطبقة الأساسية منفذة (2026-11-05، قبل الموعد)** —
> `src/durable/` كاملة (لقطات موقّعة بسلسلة تكامل + سجل تدقيق غير قابل
> للتلاعب + DurableFlow ببوابة HITL fail-closed)، اختبار حقن الفشل
> التساعي أخضر بصفر إعادة عمل، 37 اختبارًا وتغطية 99.65%. المتبقي:
> ربط الطبقة بمسار تنفيذ المنسّق والمجلس فعليًا (مُجدول ضمن م3).

**الهدف**: سد أثقل فجوتين (ض1+ض6) بأدوات LangGraph لكن بنكهتنا: حفظ عند حدود
المراحل لا داخل حلقات، وحاكمية مسجلة لا لمجرد استئناف.

**المخرجات**:
1. `src/durable/` — طبقة لقطات stdlib: JSON موقّع (hashlib) لكل حدث مرحلة
   (تصنيف مخاطر / توجيه / تفكيك / تحكيم / موافقة)، استئناف من أي نقطة، حد تكرار محسوب للحلقات.
2. HITL كعقد منتج: `interrupt(reason) / resume(decision, auditor)` مع سجل تدقيق
   غير قابل للتلاعب (append-only) لكل موافقة بشرية — مكافئ بوابتنا لـ
   interrupt/resume + tool approval (درسا §2 و§3).
3. Guardrail موحّد: تجميع risk classify + jury gate + quality gate تحت واجهة
   «سياج» واحدة معلنة (الدرس §5.3).
4. اختبار حقن الفشل المقلد لاختبار المنافسين: 9 خطوات، عطل مقصود في الخطوة 5،
   التأكيد: الاستئناف من آخر نقطة صحيحة وصفر إعادة عمل (نمنسخ معيار القياس الذي
   فاز به LangGraph ضد CrewAI — §4.3).

**بوابة الخروج**: (أ) اختبار حقن الفشل أخضر، (ب) تغطية `src/durable/` ≥95%،
(ج) كل موافقة HITL تُنتج سجل تدقيق يقرؤه اختبار.
**المخاطر**: تعقيد الاستئناف مع الوكلاء غير الحاجبين → الحل: لقطات عند حدود
المراحل فقط (بدون لقطات داخل تنفيذ وكيل جارٍ).

## 5. المرحلة 3 (م3) — الرؤية التشغيلية: تتبّع عميق · v1.55.0 · 3 أسابيع (2026-12-21 → 2027-01-08)

**الهدف**: سد ض2 — جعل كل قرار قابلًا للشرح بعد وقوعه (وعد الرؤية: «يشرح نفسه»).

- توسيع `src/observability`: صيغة تتبّع محلية (JSONL) بمعرّفات متوافقة مفاهيميًا
  مع OTel (trace/span/parent)، مع **مُصدِّر OTLP/JSON اختياري** عبر urllib فقط —
  لا يعمل إلا إذا فعّله المستخدم (الخوصصة افتراضية).
- **Replay في PWA**: تشغيل مجلس مؤرشف خطوة-بخطوة في الواجهة («ترى التفكير»
  بعد الحدث، لا أثناءه فقط).
- اختبار عقد المزوّد (ض7): اختبار عقد ثابت لواجهة `llm_router` العامة (تواقيع
  الدوال وسلوك Circuit Breaker) يفشل عند أي تغيير غير معلن.

**بوابة الخروج**: (أ) أي جلسة مجلس تُسجَّل JSONL وتُعاد بصريًا في PWA،
(ب) اختبار عقد المزوّد أخضر ويُوثَّق كواجهة مستقرة.
**المخاطر**: حجم سجلات JSONL → دوران ملفات + ضغط zlib مدمج.

## 6. المرحلة 4 (م4) — التشغيل البيني: A2A · v1.56.0 · 3 أسابيع (2027-01-11 → 01-29)

**الهدف**: سد ض3 — إكمال الثنائي المعياري (MCP ✅ + A2A ❌ → ✅).

- `src/a2a/` stdlib: بطاقة وكيل (Agent Card) تُولَّد تلقائيًا من inventory
  الأسطول (106 بطاقة من مصدر واحد للحقيقة)، نقطة نهاية رسائل، اكتشاف، وتفويض
  بين وكلائنا ووكلاء الأطر الأخرى الداعمة A2A.
- اختبار توافق: تبادل فعلي مع بطاقة وكيل مرجعية مخزنة في fixtures.
- ثنائية اتجاه: وكيلنا **يسخد** وكلاء A2A خارجيين (محدودًا بسياستنا للمخاطر
  وقاعدة الخوصصة: الاتصال الصادر يفعّل صراحةً لكل عنوان).

**بوابة الخروج**: اختبار conformance A2A أخضر (بطاقة صالحة + دورة اكتشاف/رسالة/
رد كاملة) — بلا أي اعتمادية خارجية.
**المخاطر**: تطور مواصفة A2A → نسخة المواصفة المستهدفة تُثبَّت وتُوثَّق في docs
وتُرفع بمراجعة معلنة (نفس منهجية MCP مع 2026-07-28).

## 7. المرحلة 5 (م5) — البرهان المُقاس والبوابة للمجتمع · v1.57.0 · 4 أسابيع (2027-02-01 → 02-26)

**الهدف**: سد ض5+ض8 — تحويل التميّز الداخلي إلى حجج خارجية لا تُدحض.

1. **بنشمارك منشور قابل للتكرار** `benchmarks/` + `scripts/run_benchmark.py`:
   ثلاثة سيناريوهات معيارية (مجلس تحليل عربي · تصحيح كود بحلقة · استرجاع متعدد
   الخطوات) تُقارن **دورنا الإجرائي** مع خط ReAct مباشر نفس المزوّد — النتائج
   JSON + ملخص docs/benchmarks.md يُحدَّث آليًا، مع منهجية معلنة وقيود صادقة
   (نُقاس على الجودة والتكلفة والزمن — ونعلن ما لا نكسبه، درس §8-4).
2. **البدائيات الخمس المعلنة** رسميًا في README (وكيل/مجلس/منسّق/ذاكرة/سياج) —
   الواجهة الذهنية الصغيرة التي فاز بها OpenAI SDK (§5.2).
3. **`examples/` تعليمي**: 5 أمثلة جاهزة (أول مجلس في 5 دقائق — معيار CrewAI §4.3)،
   + دليل مساهمة مبسّط + أول ADRs (سجلات قرارات معمارية) للقرارات الموجودة.
4. **CI ينشر**: تقرير أسطول + بنشمارك يتجددان آليًا في كل دمج.

**بوابة الخروج**: (أ) `scripts/run_benchmark.py` يعمل بلا إنترنت على Ollama
ويولّد تقريرًا كاملًا، (ب) الأمثلة الخمسة تُختبر آليًا (اختبار دخاني لكل مثال)،
(ج) ≥5 ADRs دامجة.
**المخاطر**: نتائج البنش غير لصالحنا في بعض السيناريوهات → نقبلها وننشرها:
المصداقية أصل استراتيجي (المشروع الذي يعلن ضعفه يُصدَّق في قوّته).
